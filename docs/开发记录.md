# 结论

这个第三方 REC（kirklin/skyward，Rust 自写 recovery，构建在小米原厂 recovery 之上）在 pudding 上「不解密 data」不是坏了，是这套构建里根本没有起解密要用的服务。

skyward 的解密实现（crates/skyward-crypto）编在 /system/bin/recovery 里，但它要靠 [[service]] 配置把手机 vendor 分区自己的 keymint / gatekeeper / qseecomd 拉起来；pudding 的 devices/pudding.toml 里只有一条 init.kernel.post_boot.sh，四条关键服务全缺。作者 README 把 pudding 列在「施工中」，并明说「不会解密 data 分区」。

# 追加（读 kirklin/skyward v0.2.0 源码后的修正）

前面四条服务只解决到「挂载 /data 的 DE 部分」，CE 解锁还差一步，原因是 weaver：

- `/data/system_de/0/spblob` 下有两个保护者：`754df7805c5a9c37`（有 `.weaver`，slot=2）与 `754df7805c5a9c38`（有 `.secdis`，16384 字节）
- `/data/system/locksettings.db` 的 `sp-handle = 8452684206321605687` = 0x754df7805c5a9c37，即指向 weaver 绑定的那一个
- v0.2.0 的 `crates/skyward-crypto/src/data.rs` 里 `protector()` 只认 sp-handle 记的那个，`open_user_files()` 的 match 只有 `Bound::Weaver` 与 `Bound::Secdiscardable` 两支，没有回退
- pudding 的 weaver 是 `/odm/bin/hw/android.hardware.weaver-service.thales`，其 `ese_weaver_thales.so` NEEDED `android.se.omapi-V1-ndk.so`，走 `keymint::javacard::OmapiTransport`；OMAPI 由 system_server 的 Java 服务提供，recovery 里没有框架 → 起不来（作者在 nezha.toml 的注释里也是这么写的）

所以正解是给 data.rs 加一条回退：当记录的保护者绑 weaver 而 weaver 未注册时，改用同目录里带 `.secdis` 与 `.pwd` 的另一个保护者（这台机器上正好存在），走 gatekeeper 校验 + keymint 解包，得到同一个合成密码。

补丁见 `补丁/weaver-fallback.diff`（基于 v0.2.0，未编译验证）。

# 追加三：卡 FB 的根因找到了 —— 我的重打包丢了 AVB 尾

对照三份能启动的镜像（原版 skyward、17 Pro、机器上的 TWRP），它们末尾都带 AVB 结构，我先前重打包的两份都没有：

- 原版：ramdisk 结束于 48674526，对齐到 48676864 处是 `AVB0` 头，512 字节；分区最后 64 字节是 `AVBf` 尾，字段 original_image_size=48676864、vbmeta_offset=48676864、vbmeta_size=512
- 17 Pro：同样结构，vbmeta_size=512
- TWRP（recovery_b）：`AVBf` 尾，vbmeta_size=0x340=832
- 我先前出的 v1 / v2 / 诊断A：ramdisk 之后全是 0，**没有 AVB0、没有 AVBf**

原版 vbmeta 的内部结构（偏移相对 vbmeta 起点）：
- 0：`AVB0`，版本 1.0；authentication_data_block_size=0、auxiliary_data_block_size=256、algorithm=NONE（**无签名**）
- 256：hash 描述符，tag=2、num_bytes_following=192
  - +16：image_size（u64）
  - +132：分区名 "recovery"
  - +140：32 字节摘要 = SHA256(image[0:image_size])，**无盐**（实测 `sha256(orig[0:48676864])` 与 +140 处 32 字节完全相等）

结论：bootloader 解析 recovery 分区时要求末尾这份 AVB 结构存在；缺了就直接不跳转、掉 fastboot。签名块是空的，所以不涉及私钥，只要按同样布局重算摘要即可。

# 修法（已做成脚本 avbwrap.py）

1. 取原镜像的 512 字节 vbmeta 与 64 字节 footer 当模板
2. 把新镜像按 4096 对齐得到长度 L，写入描述符的 image_size=L、摘要=SHA256(新镜像[0:L])
3. vbmeta 放在 L 处，footer 放分区最后 64 字节，字段改成 L / L / 512，中间补 0
4. 自检：用原包的 ramdisk 走同一套流程重建，与原件**逐字节一致**（验证通过）

# 三个必要条件（缺一即失败）

1. **AVB 尾**：缺了 bootloader 不跳转，直接进 fastboot。这是前几次卡 FB 的唯一原因。
2. **keymint + gatekeeper 能注册**：配置要直接给二进制路径与 libraries，中间不要夹 oneshot 的 shell 准备步骤。v4 就是在 `/system/bin/sh -c "mkdir -p /kmlibs && cp /mnt/system/..."` 这条 oneshot 上失败，`services::start` 直接 bail，后面所有服务一条都没起，于是连解锁页都没有。
3. **weaver 不可用时的回退**：pudding 的 weaver 是 Thales，走 OMAPI，recovery 里起不来；houji 那份二进制在 weaver 不应答时改用同一 secret 的另一个 blob（754df7805c5a9c38，gatekeeper 绑定）解 CE，所以能解锁。

# 追加六：自己编译（双系统 + weaver 回退）

```
  -L$NDK/lib/clang/21/lib/linux -L$NDK/lib/clang/21/lib/linux/aarch64 "$@"
```
cargo 环境：CARGO_TARGET_AARCH64_LINUX_ANDROID_LINKER / CC_aarch64_linux_android 指向该 wrapper，AR=ar。

源码与补丁：上游 v0.2.0（tar 包解到 构建/skyward-0.2.0），改 crates/skyward-crypto/src/data.rs：

## 十四、v18：槽位读取为空、启动提示不准、模块重复加载

### 1. 槽位读不出来（真问题）

现象：重启页「槽位 / 下次启动」显示“无法读取”，槽位切换也用不了。

根因：skyward 的 `boot::BootControl::open()` 先找 AIDL `android.hardware.boot.IBootControl/default`，
找不到再找 HIDL `android.hardware.boot@1.2::IBootControl`。**recovery 里这两个都没起**——
pudding 的 device.toml 只有 5 条服务（post_boot/qseecomd/hlosminkdaemon/onekeymint/gatekeeper-rust），
上游 nezha/popsicle/byron 与 17 Pro 的 pandora 四份配置**同样没有 boot control**，是上游的空白，不是本机特有。

本机实证：
- `/vendor/bin/hw/android.hardware.boot-service.qti` 存在，rc 为 `class early_hal / user root / group root`
- vintf 片段 `/vendor/etc/vintf/manifest/boot-service.qti.xml` 声明 `IBootControl/default`
- 系统里 `service list` 第 53 行有该服务
- 依赖 `libboot_control_qti.so`、`android.hardware.boot-V1-ndk.so`、`android.hardware.boot@1.1.so`
- `describes()` 用「包名 + 接口/实例」匹配，该片段能命中，`ready_service` 会触发 publish_descriptions

修法：device.toml 加第六条

    [[service]]
    path = "/vendor/bin/hw/android.hardware.boot-service.qti"
    libraries = ["/system/lib64", "/vendor/lib64"]
    ready_service = "android.hardware.boot.IBootControl/default"
    user = "root"
    groups = ["root"]

未验证项：AIDL 事务号。skyward 用 GET_ACTIVE=1、IS_BOOTABLE=6、IS_SUCCESSFUL=7、SET_ACTIVE_SLOT=9。
真机上用 `recovery slot` 校验：正常应打印 `next _b` 与两槽 bootable/successful；
若打印 `the boot control says slot 2 starts next`，说明 GET_ACTIVE 取到了 getNumberSlots，事务号要改。

### 10. v22：WiFi 自动打开并记住密码

设置里加一个开关（`Switch::WlanAuto` / `Effect::WlanAuto`）。文件在 `/metadata/skyward/wlan`（0600）：

```
auto=1
ssid=<十六进制>
password=<明文>
```

- 新模块 `crates/skyward/src/wlanmem.rs`：`read()` 返回 `(auto, Option<Saved>)`，另有 `set_auto` / `save` / `forget_network` / `forget`；写前把 `/metadata` remount rw，写完改回只读
- 主循环：`prepared()` 为真且 WLAN 处于 Off/Failed 时发一次 `Command::On`（worker 的 `on()` 内部会先扫一次）；扫描结果里出现记住的 SSID 就发 `Command::Join`
- `Stage::Connected` 时写回文件；`Stage::WrongPassword` 时只清网络、保留开关，免得每次开机拿错密码去试
- 手动 `Effect::JoinWlan` 也会记下密码，所以开关打开时手动连一次即被记住

### 11. 上游更新了怎么办（不是 action 按钮）

Skyward 是刷进 recovery 分区的镜像，不是 KernelSU 模块，管理器里没有「操作」按钮；action 按钮属于 KSU 模块。

REC 里「设置 → 关于 → 检查更新」那个按钮**不能用来更新这一份**：

- 它问的是 `https://api.github.com/repos/kirklin/skyward/releases/latest`（`skyward-net/src/github.rs` 的 `LATEST`）
- 只认 `skyward-<tag>-<codename>-*.zip` 这种资产，codename 是 `pudding`
- 现在上游没有 pudding 包，按了只会显示「没有这个机型的构建」
- 一旦上游真的发了 pudding 包，它会直接写进 recovery 分区，把我们这份的改动全冲掉（六条解密服务、weaver 回退、记住锁屏密码、跳过 999、首页文件管理、WiFi 自动连接）

正确路径是重编，`scripts/update-upstream.sh` 把它固化了：

```sh
RAMDISK=/path/to/ramdisk scripts/update-upstream.sh v0.3.0
```

1. 下载该 tag 源码到 `build/skyward-<tag>`
2. 打 `patches/` 里最新的补丁；先用 `--dry-run` 试，冲突就停下并列出失败文件
3. `cargo build --release -p skyward --target aarch64-linux-android`
4. 新二进制换进 `RAMDISK/system/bin/recovery`
5. `cpio` → `lz4 -l -12` → `scripts/avbwrap.py` 补 AVB，产物在 `build/out/`

补丁基于 v0.2.0，上游改动若碰到这八个文件就会冲突，通常都是加代码，手工合即可：

```
crates/skyward/src/main.rs         界面优先、槽位重读、prepared()
crates/skyward/src/ui.rs           记住密码、WiFi、三段提示
crates/skyward/src/remember.rs     新增（锁屏密码）
crates/skyward/src/wlanmem.rs      新增（WiFi 密码）
crates/skyward-crypto/src/data.rs  weaver 回退、跳过 999
crates/skyward-modules/src/lib.rs  模块去重
crates/skyward-ui/src/app.rs       开关、动作、状态
crates/skyward-ui/src/pages.rs     首页文件管理、设置里的 WiFi 开关
```

合完把补丁重出一份：`diff -ruN --exclude=target --exclude=.git <上游目录> <源码目录> > patches/skyward-pudding-<tag>.patch`。
